# Тест фичи «Визуальный стеллаж» (ручная проверка в другой сессии)

Эта инструкция проверяет фичу, добавленную на ветке `feat/box-visual-profile`
(коммиты `50660a7` … `6ea90f7`). Запускать в **отдельной сессии** — нужен живой
dev-stack (Docker + Postgres/Redis + бэкенд + фронтенд).

## Что проверяем
1. **Координаты коробок на стеллаже** — миграция добавила `box_instances.shelf_row` / `shelf_col` + partial-unique индекс (нельзя две коробки в одной ячейке).
2. **Drag&drop с сохранением позиции** — `POST /api.v1/boxes/update-box-position` (со SWAP при занятой ячейке).
3. **Сайдбар «Stellage Info»** — владелец, кол-во коробок, кол-во по редкости, цена стеллажа (сумма), поиск, фильтр по редкости.
4. **Публичный стеллаж** — `GET /api.v1/shelf/public-shelf-with-boxes` + страница `/stellage/:shelfId` (read-only, без авторизации); приватный → 404.
5. **`username`** — новое поле у `User`; на публичном стеллаже показывается username (а НЕ полный email).

## 0. Предпосылки
- Docker Desktop запущен.
- `backend/.env` существует (есть). Переменные `db_user/db_name/db_password/db_port`, redis, rabbitmq, `secret_key` и т.п.
- Poetry-окружение бэкенда установлено (`backend/.venv`). Python 3.13.
- `frontend/node_modules` установлены (есть).

## 1. Поднять инфраструктуру (Postgres/Redis/RabbitMQ)
Из `backend/`:
```bash
docker compose up -d pg redis rabbitmq
docker compose ps          # дождаться healthy у pg и redis
```
(pgAdmin по желанию: `docker compose up -d pgadmin` → http://localhost:5050)

## 2. Применить миграции
Из `backend/`:
```bash
poetry run alembic upgrade head
```
Должны примениться (в т.ч.) две новые ревизии:
- `b7c4e9f1a2d3` — `add_box_shelf_position` (колонки `shelf_row`, `shelf_col`, индекс `uq_box_instances_shelf_position`);
- `c1a2b3d4e5f6` — `add_user_username` (колонка `users.username`, индекс `uq_users_username`).

Проверка (через pgAdmin или psql в контейнере pg):
```sql
\d box_instances     -- видны shelf_row, shelf_col
\d users             -- видна username
```

## 3. Запустить бэкенд и фронтенд
Бэкенд (из `backend/`), слушает `127.0.0.1:8000`:
```bash
poetry run app
# или для авто-перезагрузки:
poetry run uvicorn stellage.main:app --reload --port 8000
```
Swagger: http://127.0.0.1:8000/docs

Фронтенд (из `frontend/`), Vite на `127.0.0.1:5173` и проксирует `/api.v1` → `:8000`:
```bash
npm run dev
```
Открыть http://127.0.0.1:5173

## 4. Завести тестового пользователя (с username)
1. На `/register` зарегистрироваться, **заполнив поле «Имя пользователя»** (напр. `alex`), email и пароль (≥8 символов).
2. Регистрация шлёт письмо-подтверждение через Celery/RabbitMQ. Воркер в dev обычно не запущен, поэтому **подтвердите пользователя напрямую в БД** (быстрый путь):
   ```sql
   UPDATE users SET is_verified = true, is_active = true WHERE email = '<твой email>';
   ```
   (psql в контейнере: `docker exec -it $(docker compose ps -q pg) psql -U <db_user> -d <db_name>`)
   Альтернатива: запустить celery-воркер и перейти по ссылке из письма.
3. Войти на `/login`.

> Проверка username: `SELECT email, username FROM users;` — у нового пользователя `username = 'alex'`.

## 5. Засеять данные через Swagger (UI создания коробок ещё нет)
На http://127.0.0.1:8000/docs (куки-сессия уже стоит после логина в браузере; для Swagger можно логиниться через `/api.v1/auth/login`):
1. **Создать главный стеллаж** — `POST /api.v1/shelf/create-shelf`:
   ```json
   { "title": "Мой стеллаж", "is_main": true, "is_public": true }
   ```
   Запомнить `id` из ответа — это `shelfId` для публичной проверки. Поле `is_public: true` обязательно для шага 8.
2. **Создать шаблон коробки** — `POST /api.v1/boxes/create-box-template` (повторить с разными `rarity`, напр. `COMMON`, `RARE`, `GOLDEN`):
   ```json
   { "title": "Base", "description": "test", "price": 100, "currency": "RUB", "rarity": "COMMON" }
   ```
3. **Создать несколько экземпляров на стеллаже** — `POST /api.v1/boxes/create-box-instance` (4–8 шт, можно разные шаблоны):
   ```json
   { "template_id": "<id шаблона>", "shelf_id": "<id стеллажа>" }
   ```
   Координаты можно не задавать — фронтенд сам разложит по свободным ячейкам.

## 6. UI: своя полка (`/my-stellage`)
- [ ] Открывается «доска» с горизонтальными полками-линиями; коробки стоят на линиях по сетке (по умолчанию 5 рядов × 8 колонок), без наложений.
- [ ] Слева сайдбар «Stellage Info»: **Владелец** = `alex` (username), **Кол-во коробок** = N, блок **По редкости** с подсчётом, **Цена стеллажа** = сумма `price` всех коробок + валюта.
- [ ] **Поиск коробки** фильтрует доску по названию/серийному номеру.
- [ ] **Фильтр по редкости** (чипы) — оставляет только выбранные редкости.

## 7. UI: drag&drop и SWAP
- [ ] Перетащить коробку в **пустую** ячейку → отпустить → коробка встаёт в новую ячейку.
- [ ] **Перезагрузить страницу (F5)** → коробка осталась на новом месте (позиция сохранилась в БД).
- [ ] Перетащить коробку **на занятую** ячейку → две коробки **меняются местами** (SWAP), после F5 обмен сохранён.
- [ ] Проверка в БД: `SELECT serial_number, shelf_row, shelf_col FROM box_instances WHERE shelf_id = '<id>' ORDER BY shelf_row, shelf_col;` — нет двух одинаковых пар `(shelf_row, shelf_col)`.

## 8. UI: публичный стеллаж (read-only, без авторизации)
- [ ] Открыть `http://127.0.0.1:5173/stellage/<shelfId>` в **приватном окне** (без сессии).
- [ ] Доска и сайдбар отображаются; **перетаскивание отключено** (курсор обычный, позиции не меняются).
- [ ] **Владелец** показан как **username** (`alex`), а **не** полный email. (Если у пользователя username пуст — должна показываться только локальная часть email, без `@домена`.)
- [ ] Сделать стеллаж приватным и проверить 404: `PATCH/POST` нет — проще создать второй стеллаж с `is_public: false` и открыть его публичный URL → ожидается ошибка загрузки (бэкенд отдаёт **404**).

## 9. Проверки на уровне API (Swagger или curl)
- [ ] `POST /api.v1/boxes/update-box-position?instance_id=<id>` с телом `{ "shelf_row": 0, "shelf_col": 0 }` → 200, в ответе обновлённая коробка. Повторный вызов на занятую ячейку → SWAP (вторая коробка уезжает на прежние координаты первой), без ошибки уникального индекса.
- [ ] `GET /api.v1/shelf/public-shelf-with-boxes?shelf_id=<публичный id>` → 200, есть `owner_username`, есть `boxes[]` с `shelf_row/shelf_col`.
- [ ] Тот же эндпоинт с `shelf_id` приватного стеллажа → **404**.

## Критерии прохождения
Все чекбоксы выше отмечены. Ключевое: позиции сохраняются и переживают перезагрузку; нет двух коробок в одной ячейке (SWAP работает); публичный стеллаж read-only и показывает username, а не email; приватный — 404.

## Известные ограничения / follow-ups
- Публичный эндпоинт отдаёт **все** коробки стеллажа независимо от `is_public` самой коробки (фильтрация по видимости коробки — отдельная задача).
- `username` опционален при регистрации; у старых пользователей он `NULL` → на публичном стеллаже подставляется локальная часть email (полный email не раскрывается).
- Публичное чтение идёт мимо Redis-кэша (кэш ключей привязан к `user_id`); при необходимости — отдельный неперсонализированный кэш.
