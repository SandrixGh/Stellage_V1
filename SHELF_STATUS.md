## Известные проблемы (требуют исправления)

### P1 — Коробка не появляется на полке сразу после постановки
**Симптом (пользователь):** После клика «На полку →» коробка исчезает из инвентаря, но на стеллаже не появляется — нужно вручную обновлять страницу.

**Причина:** `moveBox` в сторе вызывает `fetchMainShelf()` (с await), а `fetchInstances()` — без await (fire-and-forget). Из-за этого инвентарь обновляется немедленно (коробка уходит из лотка), а стейт `mainShelf.boxes` возможно ещё не успел обновиться до ре-рендера. Плюс: если пользователь смотрит на не-главную полку через переключатель, `selectedShelf` вообще не обновляется после `moveBox` — обновляется только `mainShelf`.

**Файл:** `frontend/src/store/useStellageStore.ts` → `moveBox`

**Исправление:**
```ts
moveBox: async (instanceId, shelfId) => {
    await api.post(…);
    await Promise.all([get().fetchMainShelf(), get().fetchInstances()]);
    // Если shelfId это не-главная полка — дополнительно fetchShelfWithBoxes(shelfId)
},
```

### P2 — «Стековое» поведение: новая коробка занимает первую ячейку и ломает расстановку
**Симптом (пользователь):** Поставив коробку через инвентарный лоток, она попадает на первую свободную ячейку (0,0 → 0,1 → …), что может разрушить уже сложившийся красивый порядок на полке.

**Причина:** `move-box-to-shelf` устанавливает `shelf_id`, но **не сохраняет координаты** (они остаются `null` в БД). `ShelfBoard.placeBoxes` визуально раскладывает коробки с `null`-координатами в первую свободную ячейку в row-major порядке — каждый раз может быть другая. После перезахода позиция коробки «плавает».

**Файл:** `frontend/src/pages/Main/MainPage.tsx` → `handlePlaceOnShelf`, `useStellageStore.ts` → `moveBox`, `ShelfBoard.tsx` → `placeBoxes`

**Правильное поведение:** При постановке через лоток коробка должна занять первую свободную ячейку, и эта позиция должна немедленно сохраниться на бэкенде через `POST /boxes/update-box-position`. Тогда после перезахода коробка стоит ровно там же.

**Исправление:** После вызова `move-box-to-shelf` вычислить позицию `placeBoxes` для новой коробки в контексте текущего стеллажа и сразу вызвать `update-box-position` с полученными `shelf_row/shelf_col`.

### P3 — Визуал коробки на полке не соответствует референсу
**Симптом (пользователь):** Коробка на стеллаже показывается в виде карточки с тёмным фоном-канвасом, порядковым номером `#N`, именем и тегами. Это лишнее; смотрится перегруженно.

**Референс (второй скриншот):** Только wireframe-геометрия коробки, стоящая прямо на линии полки. Под коробкой на линии полки — бирка: крупный текст с названием, под ним — тег редкости.

**Файл:** `frontend/src/components/Stellage/BoxCard.tsx`, `frontend/src/components/Stellage/BoxCard.css`, `ShelfBoard.tsx` (обёртка `.shelf-cell-inner`)

**Что убрать / изменить:**
- Убрать фоновый `div.box-card` с `border`, `background`, `backdrop-filter` — никакой «карточки».
- Убрать блок `box-card-serial` (`#N` и галочку верификации) с видимого отображения на полке.
- Убрать блок `box-card-info` (имя + теги) из самой карточки.
- Вместо этого: `<WireframeBox>` напрямую на ячейке + бирка под ним на уровне линии полки:
  ```
  [WireframeBox — без фона]
  ─────────────── shelf line ───────────────
  [ NAME · RARITY TAG ]  ← бирка на полке
  ```
- Бирка стилизуется как тёмный прямоугольник с лёгкой подложкой, прилегающий к линии полки снизу.

### P4 — `updateBoxPosition` (drag) работает только на главной полке
**Симптом:** При переключении на тематическую (не-главную) полку перетаскивание визуально срабатывает, но позиция не сохраняется и откатывается.

**Причина:** `updateBoxPosition` в сторе оптимистично обновляет `mainShelf.boxes`, а не `selectedShelf`. Если `currentShelf` — это `selectedShelf`, изменения теряются.

**Файл:** `useStellageStore.ts` → `updateBoxPosition`, `MainPage.tsx` → `onMove` prop

**Исправление:** `onMove` должен знать, с каким шелфом работает: передавать `currentShelf.id` и обновлять либо `mainShelf`, либо `selectedShelf` в зависимости от того, что активно.
